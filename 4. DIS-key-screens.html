00 / Foundation

Overall Screen Strategy

Every screen is built on a consistent shell — left sidebar navigation, top header with context and actions, main content area. This predictable structure means users always know where navigation is, where page title is, and where the primary action lives.

Universal Layout Shell

  • Left sidebar (200px): Primary navigation — always visible on desktop
  • Top header: Page title + breadcrumb + contextual action buttons
  • Content area: Full-width, scrollable, max-width 1280px
  • Content grid: 12 columns, 16px gutters, responsive breakpoints
  • Utility nav (top-right): Notifications bell, settings gear, user avatar

Content Priority Rules

  • Every screen answers two questions: "What do I need to know?" and "What should I do next?"
  • Critical metric (score/premium/status) is always above the fold — no scroll needed for primary data
  • Primary CTA always in the header actions zone or as a prominent card CTA
  • Secondary information lives below the fold or in expandable sections
  • Alerts surface at the top of content, never buried in a sidebar

Data Presentation Decisions

  • Numbers in serif/mono at display size for instant legibility
  • Trends shown as sparklines or mini bar charts — not full-page charts
  • Status always communicated via color + text + icon (never color alone)
  • Raw data hidden behind progressive disclosure — always translated first
  • Blockchain data abstracted as "Verified" badge — never raw hashes

Navigation Hierarchy

  • L1 (Sidebar): Dashboard · My Score · Trips · Insurance · Claims · Rewards · Settings
  • L2 (Tabs/sub-nav): Within each section — e.g., Insurance has Policy/Premium/Payments/Renewal
  • L3 (Drill-down): Trip detail, claim detail — breadcrumb back navigation
  • Active state: left border highlight + background tint + bold label
01 / Primary Screen

Dashboard — Primary Landing Screen

The most important screen. Every returning user lands here. Score dominates the visual hierarchy — everything else supports it. Layout uses a 3-column asymmetric grid: score+trend (60%) / alerts+actions (40%) above fold. KPI row and trip list below.

Layout Strategy
Zone 1 (above fold): Score hero + 7-day trend sparkline + current premium + active alert card. Zone 2: 4-column KPI row (streak, trips this week, avg score, discount earned). Zone 3: Quick actions row. Zone 4: Recent trips list. Content priority flows top→bottom by usage frequency.

Visual Hierarchy — Priority Order

  • P1 — Score ring + trend: Dominant, above fold, 50% of above-fold width
  • P2 — Premium card: Equal billing with score — the financial outcome
  • P3 — KPI row: Supporting data, scannable in under 5 seconds
  • P4 — Alert: Amber border, always visible when active
  • P5 — Quick actions: 4-grid, large tap targets
  • P6 — Recent trips: Context, scrollable list

Interaction Behaviors

  • Score ring animates on load: sweeps from 0 to value (0.8s)
  • KPI numbers count-up animation on first render
  • Alert row has dismiss (swipe/X) with 4s undo toast
  • Quick action cards: hover background tint + border color shift
  • Trip rows: hover border highlight, click → trip detail slide-in
  • Premium card: "View breakdown" expands to full insurance screen

11 / System States

States, Responsive & Design Rules

Hover & Active States

  • Cards: Border transitions from N-200 → brand-md on hover (0.15s)
  • Buttons: Primary darkens 8%; secondary fills brand-lt background
  • Table rows: Background shifts to N-50 on hover
  • Nav items: Background tint on hover; active: left border + deeper tint
  • Trip cards: Slight elevation increase (box-shadow) on hover

Loading States

  • Dashboard: Skeleton screens for score ring, KPI row, trip list — no spinners
  • Skeleton respects layout — placeholder shapes match final content structure
  • Score calculation in progress: animated ring pulse + "Calculating…" text with educational copy below
  • Table loading: 5-row skeleton table, column widths match actual table
  • Blockchain sync: "Pending verification" badge with animated dot

Empty States

  • No trips: Illustration + "Connect your OBD and start driving" + CTA
  • No claims: "No claims filed — safe driving keeps this list empty" + positive tone
  • Analytics empty: Dashed chart placeholder + "Complete trips to see your data"
  • All done: Celebratory empty state — "You crushed it today! 🎉" — no action pressure
  • All empty states have a single primary CTA — never two choices

Error States

  • Form validation: Inline, below field, red text + icon — never modal
  • Network error: Non-blocking amber banner — cached data shown below
  • OBD disconnected: Non-blocking teal banner with reconnect deep-link
  • Claim rejection: Full explanation + specific reason + re-submission CTA
  • No permission: Locked section visual with Settings link — never a crash state

Responsive Breakpoints

  • Desktop ≥1280px: Full sidebar + full content, all columns visible
  • Laptop 1024–1279px: Sidebar collapses to 64px icon-only mode
  • Tablet 768–1023px: Sidebar hides behind hamburger; 2-column grids become 1-column
  • Mobile <768px: Bottom navigation bar replaces sidebar; KPI grid 2×2; all tables become card stacks
  • Score ring and premium always above fold at all breakpoints

Consistency Rules

  • Every page header follows: title (left) + breadcrumb (below title) + actions (right)
  • Primary CTA is always rightmost in the header actions zone
  • Section headings always 11px 700 with a "View all →" link right-aligned
  • Status badges always: color + dot + text — never color alone
  • Numbers in data positions always use Lora (serif) — never sans-serif
  • Blockchain badges always appear at the bottom of the relevant card, never dominant
